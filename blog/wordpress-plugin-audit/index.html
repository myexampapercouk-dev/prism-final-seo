WordPress Plugin Audit: How to Review, Remove and Replace Plugins

How to run a WordPress plugin audit: list what is installed, check each plugin is needed, maintained and safe, then remove or replace them safely.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Audit plugins by asking of each one: is it needed, is it maintained, does it overlap with another, and what does it cost in speed and risk.
  • Always back up and test on a staging copy before deactivating or removing plugins on a live site.
  • Deactivated plugins should usually be deleted, and the audit repeated regularly rather than once.

Plugins are what make WordPress so flexible. They are also where many WordPress problems start. Over time, sites collect plugins that were installed for a one-off task, replaced by something else, or added by someone who has since left. Each extra plugin is more code to update, more potential for conflicts and another possible way in for attackers.

A plugin audit is a structured review of every plugin on your site, deciding what stays, what goes and what should be replaced. This guide explains how to do one safely. It complements our WordPress security guide and website maintenance guide.

Why audit your plugins?

  • Security. Outdated or abandoned plugins are a well-known route for attacks on WordPress sites. Fewer plugins, kept up to date, means fewer weak points.
  • Speed. Some plugins load scripts and styles on every page, even where they are not used. Removing them can make pages lighter. Our website speed guide covers this in more detail.
  • Stability. Plugins that overlap or clash can cause errors, especially after updates.
  • Cost. Premium plugins often renew annually. An audit can reveal licences you are paying for but no longer need.
  • Clarity. Knowing what each plugin does makes future changes and handovers far easier.

Before you start: protect the site

Deactivating the wrong plugin can break a layout, a form or a checkout. Before changing anything:

  1. Take a full backup of files and database, stored away from the live server. Check that the backup includes both parts; a copy of the files without the database will not restore a working site.
  2. Set up a staging copy of the site if you can, so you can test changes without affecting visitors. Many hosts offer this.
  3. Pick a quiet time for any changes to the live site.

Step 1: List every plugin

Go to Plugins in the WordPress dashboard and record each one in a spreadsheet. For each plugin, note:

  • Name and version.
  • Active or inactive.
  • Free or premium, and renewal date if premium.
  • What it does, in one plain sentence.
  • Where on the site it is used.
  • When it was last updated by its developer.

Also check for must-use plugins, which appear under a separate Must-Use tab if present, as they cannot be deactivated from the normal list and are sometimes added by hosts.

If you cannot say what a plugin does, that is a finding in itself. Search the plugin's description in the dashboard, and check its settings page, to work out its purpose before deciding anything.

Step 2: Ask four questions of each plugin

Is it needed?

Does the site still use this feature? Plugins installed for a past campaign, an old contact form, a migration or a design that has since changed are common candidates for removal. If nobody can point to where it is used, test the site without it on staging.

Is it maintained?

Check when the plugin was last updated and whether it is marked as tested with your version of WordPress. A plugin that has not been updated for a long time may be abandoned. If a plugin has been closed or removed from the WordPress.org plugin directory, find out why, as this is sometimes due to an unresolved security issue. An abandoned plugin is not automatically dangerous, but it will not be fixed if a problem is found.

Does it overlap with something else?

Sites often end up with two plugins doing the same job, such as two SEO plugins, two caching plugins or two form builders. Overlap can cause conflicts and duplicate output, like two sets of meta tags. Pick one and remove the other. Also check whether WordPress itself, your theme or your host now provides the feature, which can make a plugin redundant.

What does it cost?

Consider cost in money, speed and risk. A plugin that loads heavy scripts on every page to power a feature on one page may be worth replacing with something lighter or a small piece of custom code. Weigh this against the effort and risk of changing it.

Step 3: Sort plugins into groups

DecisionWhen it applies
KeepNeeded, maintained, no overlap, reasonable cost
UpdateNeeded, but running an old version
ReplaceNeeded, but abandoned, overlapping or heavy
RemoveNo longer used, or duplicated by another plugin or by WordPress itself
InvestigatePurpose unclear, or removal might affect something important

Step 4: Make changes one at a time

On staging, work through the list. Deactivate one plugin, then check the site. Test the pages and features that plugin might affect, plus the core journeys: home page, key landing pages, contact forms and, for WooCommerce, product pages, basket and checkout in test mode. Only move on when you are happy.

Changing several plugins at once makes it hard to tell which change caused a problem. One at a time is slower but much safer.

When replacing a plugin, check what data it stores. Some plugins hold content, settings or form entries that will not transfer automatically to a replacement. Export anything you need first.

Step 5: Delete, do not just deactivate

A deactivated plugin is not running, but its files remain on the server. Depending on the plugin and server set-up, those files could still pose a risk if they contain a vulnerability. Once you are sure you do not need a plugin, delete it. Some plugins leave data in the database after deletion; check the plugin's documentation for an option to remove its data if you want a cleaner database.

Step 6: Apply to live and keep a record

Once the changes work on staging, take a fresh backup of the live site and repeat the same changes there, in the same order. Check the site again afterwards. Keep your spreadsheet as a record of what is installed and why. It becomes a useful reference for future updates, developer handovers and the next audit. Our ownership and handover guide explains why that kind of documentation matters.

Signs a plugin needs attention

  • It has not been updated for a long time.
  • It shows a warning that it has not been tested with your WordPress version.
  • The site shows errors or slows down after the plugin updates.
  • It adds admin notices or upsells you cannot dismiss.
  • Its premium licence has lapsed, so updates have stopped.
  • Nobody knows why it was installed.

Questions to ask before installing a new plugin

The easiest plugin to manage is the one you never install. Before adding anything new, ask a few questions. Can WordPress, your theme or an existing plugin already do this? Is the plugin actively maintained and tested with your WordPress version? Does it load code across the whole site for a feature used on one page? Is there a clear way to remove it, and its data, later if you change your mind? If it is premium, who holds the licence, and will updates stop if it lapses? Adding the answers to your plugin spreadsheet at the point of installation keeps the record up to date and makes the next audit quicker.

How often to audit

There is no fixed rule, but a review every few months, plus a check whenever you add a plugin or redesign part of the site, keeps things under control. Updates themselves should happen far more often than audits; keeping plugins updated is part of routine maintenance.

Plugins on WooCommerce shops

WooCommerce shops tend to rely on more plugins for payments, shipping, tax and marketing. These are often business-critical, so be especially careful. Test checkout and order emails after every change, and avoid making changes during busy trading periods. FAQs

How many plugins is too many for WordPress?

There is no magic number. What matters is whether each plugin is needed, maintained and well built. A few poorly made plugins can cause more trouble than many good ones.

Is it safe to delete inactive plugins?

Usually yes, if you are sure they are not needed. Take a backup first and check whether the plugin stores data you want to keep.

How do I know if a plugin is abandoned?

Check its last update date and whether it is marked as tested with recent WordPress versions. Long gaps without updates suggest it may no longer be maintained.

Can removing a plugin break my site?

It can, if something depends on it. That is why you should back up, test on staging and remove plugins one at a time.

Do plugins slow WordPress down?

Some do, particularly those that load scripts on every page. Removing unnecessary plugins is often one of the simpler ways to lighten a site.
