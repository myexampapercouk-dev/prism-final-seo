WordPress Site Health Screen: How to Read It and What to Do About It

A practical guide to the WordPress Site Health screen: what the status and info tabs show, which warnings matter, and how to act on them safely.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Site Health is a built-in WordPress check that flags configuration, security and performance issues in plain language.
  • Critical issues deserve prompt attention, while recommended improvements can often be planned into routine maintenance.
  • Many fixes involve hosting or server settings, so check with your host and test on staging before changing anything significant.

WordPress includes a built-in check-up tool called Site Health. It looks at how your site and server are configured and lists anything it thinks could cause problems, from outdated software to missing security features. For many site owners, it is the first sign that something needs attention, but the messages can be confusing, and not every warning carries the same weight.

This guide explains where to find the Site Health screen, what the two main tabs show, how to interpret the common types of message, and how to act on them without causing new problems. It is written for site owners and editors rather than developers.

Where to find Site Health

In the WordPress dashboard, go to Tools and then Site Health. You need an administrator account to see it. There is also a Site Health status widget on the main dashboard, which gives a quick summary and links to the full screen.

The screen has two tabs: Status and Info. Status lists the results of WordPress's automated tests. Info gives a detailed technical snapshot of your site and server.

The Status tab

At the top of the Status tab, WordPress shows an overall indicator. Below it, results are grouped into categories:

  • Critical issues. Problems that WordPress considers important, such as a server running an outdated version of PHP, or a site that cannot communicate with WordPress.org.
  • Recommended improvements. Things that would make the site better or safer but are less urgent, such as inactive themes being left installed.
  • Passed tests. Checks that found nothing wrong. These are collapsed by default.

Each result can be expanded to show a short explanation and, often, a suggested action. Results are also labelled by area, such as security or performance.

The overall indicator is a summary, not a score to chase. A site with one important recommendation outstanding may matter more than a site with several minor ones. Read the individual items rather than focusing on the headline.

Common Site Health messages and what they mean

The exact tests depend on your WordPress version and anything added by installed extensions, but certain themes come up often.

Outdated PHP version

PHP is the programming language WordPress runs on. Older versions stop receiving security updates and can be slower. If Site Health flags your PHP version, the upgrade usually happens through your hosting control panel or by asking your host. Before upgrading, check that your theme and extensions support the newer version, and test on staging, because older code can break.

Inactive themes and plugins

Site Health may recommend removing inactive themes and plugins. Even when switched off, outdated code on the server can be a security risk. Keep one default theme as a fallback if your setup allows, and remove anything you no longer need. Our WordPress plugin audit guide explains how to review what is installed.

Updates available

If WordPress core, themes or extensions have pending updates, Site Health will usually say so. Updates often include security fixes, so they are worth applying, but a routine of backing up and testing first is sensible. Our website maintenance guide covers how to plan update routines.

HTTPS not fully enabled

Site Health checks whether your site uses HTTPS. If it reports that the site address is not set to HTTPS, or the certificate has a problem, the fix usually involves your host and the WordPress address settings. Changing the site address incorrectly can lock you out, so take a backup and proceed carefully.

Background updates not working

WordPress can install some updates automatically. If Site Health reports that background updates are not working, it may be because of file permissions or server configuration. Some sites deliberately disable automatic updates, so this message is not always a problem, but you should know which situation you are in.

Loopback and REST API errors

WordPress sometimes needs to send requests to itself, known as loopback requests, and uses its REST API for features such as the block editor. If either fails, scheduled tasks and editing features can misbehave. Causes include security rules, firewall settings or a conflict with an installed extension. These usually need investigation rather than a quick fix.

Scheduled events running late

WordPress uses a scheduling system for tasks such as publishing scheduled posts and running maintenance jobs. If events are running late, it can be because the site has little traffic, because loopback requests are failing, or because of hosting configuration. Your host or developer can advise on a more reliable approach.

Persistent object cache recommended

On some sites, Site Health suggests using a persistent object cache, which can help performance on busier sites. Whether this is worthwhile depends on your hosting and traffic. It is a conversation to have with your host rather than a setting to switch on blindly. Our guide to website speed optimisation covers performance more broadly.

Debug mode enabled

If WordPress debug mode is turned on in a live site, Site Health may warn that errors could be shown to visitors. Debug mode is useful during development but generally should be off on a live site, or set up so errors are logged rather than displayed.

The Info tab

The Info tab lists detailed technical information about your site, grouped into sections such as WordPress, the active theme, plugins, media handling, the server, the database and file permissions. Most of the time you will not need it, but it is very useful when something goes wrong.

There is a button to copy the site information to the clipboard. Sharing this with a developer or host can save time when diagnosing a problem, because it answers many of the first questions they would ask. Before sending it, read through what is included. It can contain details about your server and file paths, so share it only with people you trust and through a sensible channel.

How to act on Site Health results

A simple approach helps avoid making things worse.

Triage

Start with critical issues, especially anything related to security or outdated software. Recommended improvements can usually be grouped into your next maintenance session.

Back up first

Before any change to server settings, PHP versions or core configuration, take a full backup and check you know how to restore it. Our backup and recovery guide covers what a good backup routine includes.

Test on staging

Where possible, make changes on a staging copy, check the site works, then repeat on the live site. Our guide to website staging and testing explains how.

Involve your host where needed

Many Site Health items, such as PHP versions, HTTPS certificates and server modules, are controlled by your hosting environment. Your host is often best placed to help. If your host cannot support current requirements, it may be time to review your hosting. Our guide to WordPress hosting covers what to look for.

Recheck

Site Health reruns tests when you visit the screen, so return after making changes to confirm the issue has cleared.

What Site Health does not do

Site Health is a useful check, but it is not a full audit. It does not:

  • Scan for malware or confirm that your site has not been compromised.
  • Test accessibility, content quality or user experience.
  • Check that backups exist and can be restored.
  • Review user accounts and permissions in depth.
  • Measure real-world page speed for visitors.

Treat a clean Site Health screen as a good sign, not a guarantee. Our WordPress security guide and our guide to WordPress user roles cover areas that Site Health does not reach.

Making Site Health part of routine maintenance

A quick look at Site Health during regular maintenance helps you catch problems early. A simple routine might be: check for updates, review Site Health, take a backup, apply updates on staging, test, then update live. Note any items you have decided to leave, and why, so the next person looking does not repeat the investigation.

Some extensions add their own tests to Site Health. If you see a message you do not recognise, check which component added it before acting.

FAQs

Where is Site Health in WordPress?

Go to Tools, then Site Health, in the WordPress dashboard. You need an administrator account to see it.

Do I need to fix every Site Health recommendation?

Not always. Critical issues deserve prompt attention, while recommended improvements can be weighed up and planned into maintenance. Some may not apply to your setup.

Is it safe to upgrade PHP when Site Health suggests it?

It is usually worthwhile, but check that your theme and extensions support the newer version, take a backup and test on staging first.

Does Site Health check for malware?

No. It checks configuration and settings, but it does not scan for malware or confirm that a site is clean.

Should I share my Site Health info with a developer?

It can speed up troubleshooting. Read it first, as it includes server details, and share it only with people you trust.
