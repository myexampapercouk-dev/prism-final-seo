Website Tables on Mobile: How to Make Tables Readable on Small Screens

Practical ways to make website tables work on mobile, from scrolling tables to stacked cards, for price lists, size guides, opening hours and comparisons.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Tables suit genuinely tabular information, but wide tables need a deliberate plan for small screens.
  • Common approaches include horizontal scrolling, stacked cards, hiding less important columns and splitting large tables.
  • Use proper table markup with headers so screen readers can make sense of the data.

Tables are one of the clearest ways to present certain information: a size guide, a price list, opening hours, a delivery rates chart or a comparison of service packages. On a desktop screen they work well. On a phone, a table with five or six columns can turn into a cramped grid of squashed text, or spill off the edge of the screen so the page wobbles sideways.

Many visitors to small business websites browse on their phones, so tables need a plan for small screens. This guide explains when to use a table, the main approaches to making tables mobile friendly, and how to keep them accessible. It applies whether your site is on WordPress, Shopify or another platform.

When a table is the right choice

Tables are for data with rows and columns that relate to each other, where people compare values across a row or down a column. Good examples include:

  • Clothing size guides with chest, waist and length measurements.
  • Delivery options with cost and timescale for each region.
  • Opening hours by day.
  • Service packages compared feature by feature.
  • Technical specifications for products.

Tables are not for page layout. Older websites sometimes used tables to arrange content into columns, which causes problems for screen readers and mobile layouts. Use your theme or page layout tools for columns instead.

Also ask whether a table is needed at all. A list of three services with a price each might read better as a simple list or a set of cards on every screen size.

Why tables struggle on mobile

A phone screen is narrow. A table has a natural minimum width set by its content: column headers, long words and numbers cannot shrink indefinitely. When the table is wider than the screen, one of a few things happens: text is squeezed until it wraps one word per line, the table overflows and the whole page scrolls sideways, or the browser shrinks everything until it is unreadable.

Sideways scrolling of the whole page is particularly unpleasant. It breaks the layout of everything else on the page and can make navigation hard to reach. Whatever approach you choose, the aim is to keep the rest of the page stable.

Approach one: let the table scroll on its own

The simplest fix is to wrap the table in a container that scrolls horizontally, while the rest of the page stays put. The visitor swipes sideways within the table to see more columns.

This works well for tables people read row by row, such as size guides, and keeps the structure intact. To make it work well:

  • Show a visual hint that more columns exist, such as a fade at the edge or a short note saying "Swipe to see more".
  • Consider keeping the first column fixed so people can still see which row they are reading as they scroll.
  • Keep the number of columns manageable so scrolling is short.

Many WordPress block themes and Shopify themes already wrap tables in a scrolling container. Check yours on a phone before adding anything.

Approach two: stack rows into cards

On small screens, each row can be displayed as a card, with each value shown alongside its column heading. A service comparison row becomes a card for one package, listing each feature and its value underneath.

This avoids sideways scrolling entirely and suits tables with many columns but relatively few rows. It is less suitable when people need to compare values across rows, because comparing two cards means scrolling up and down.

Stacked layouts usually need some custom styling from a developer. Care is needed so the underlying markup remains a proper table for assistive technology.

Approach three: prioritise columns

Not every column is equally important. On a phone you might show the two or three most useful columns and offer the full table behind a link or toggle. A delivery table might show region and cost on mobile, with timescales available on tap.

Be careful with this approach. Hiding information that some visitors need can cause frustration or extra enquiries. Only hide columns that are genuinely secondary, and make it clear how to see them.

Approach four: split or reshape the table

Sometimes the best fix is editorial. A large comparison table could become several smaller tables, one per category. A size guide covering tops, trousers and shoes could be three separate tables, perhaps using tabs or headings. A table with columns for each day of the week might work better turned on its side, with days as rows.

Swapping rows and columns is often the quickest win: phones have plenty of vertical space but little horizontal space, so long and narrow tables tend to fit better than short and wide ones.

Writing tables that fit

Content choices make a big difference before any styling.

  • Short headers: "Price" instead of "Price including VAT per month". Put the detail in a note under the table if needed.
  • Consistent units: state the unit in the header once, such as "Chest (cm)", rather than repeating it in every cell.
  • Abbreviations with care: only use ones your audience will understand, and explain them nearby.
  • Avoid long sentences in cells: tables suit short values. Longer explanations belong in the text around them.

Accessibility basics for tables

Screen reader users navigate tables cell by cell, hearing the relevant header for each value. That only works if the table is built with proper header cells. When using the WordPress table block, enable the header row option. In Shopify, tables added through the rich text editor or theme sections should also mark header cells, although what is possible depends on the editor and theme.

Other good practices:

  • Give the table a caption or a heading directly above it explaining what it shows.
  • Avoid merged cells where possible, as they are harder to interpret.
  • Do not put tables in images. Text in images cannot be read by screen readers, resized or searched, and often looks blurry on phones.
  • Check contrast for header rows and any striped row backgrounds.

Our guide to website accessibility covers these principles in more depth.

Tables on Shopify product pages

Size guides and specifications are frequent table uses on Shopify stores. Rather than pasting the same table into every product description, consider storing it once and displaying it through a theme section, a page linked from the product, or structured product data. Our article on Shopify metafields explains how product-specific details can be stored in fields and shown consistently.

A size guide in a pop-up or drawer can work well on mobile, as long as it scrolls properly and closes easily.

Tables in WordPress

The block editor includes a table block with options for a header row, footer row and fixed-width cells. Fixed-width cells make columns equal widths, which can help or hurt depending on content. Test both on a phone. Our WordPress block editor guide covers the editor more broadly.

For larger or frequently updated tables, a developer can build a reusable pattern or a custom block so the mobile behaviour is consistent across the site.

Testing tables on real devices

Browser tools that simulate phone screens are useful, but testing on an actual phone is better. Check that:

  • The page does not scroll sideways as a whole.
  • Text in cells is large enough to read without zooming.
  • It is clear when a table scrolls and how to see the rest.
  • Headers remain understandable when columns are narrow.

FAQs

What is the easiest way to make a table work on mobile?

Wrapping the table in its own horizontally scrolling container is usually simplest. It keeps the table intact while stopping the whole page from scrolling sideways.

Should I use an image of a table instead?

No. Images of tables cannot be read by screen readers, are hard to update and are often unreadable on phones. Use a real table.

How many columns are too many for mobile?

It depends on the content. If the table needs a lot of sideways scrolling, consider swapping rows and columns, splitting it or using stacked cards.

Do tables affect SEO?

Search engines can read properly built tables. A clear, usable table helps visitors, which is the main goal, and a heading above it gives useful context.

Can I hide columns on mobile?

You can, but only hide genuinely secondary information and provide a clear way to view it. Hiding essential details can frustrate visitors.

Is a pricing table the same as a data table?

Not always. Package comparisons are often better as cards with feature lists. Our pricing page design guide covers that layout.
