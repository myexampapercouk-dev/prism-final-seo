Website Redirects When Relaunching: Protect Your Search Traffic

How to plan website redirects when you relaunch, redesign or change platform, so visitors and search engines reach the right pages and rankings are protected.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Map every important old URL to its closest new equivalent before launch, not after.
  • Use permanent redirects for moved pages and avoid chains, loops and mass redirects to the homepage.
  • Check redirects, Google Search Console and broken links in the days and weeks after going live.

A redirect sends visitors and search engines from an old web address to a new one automatically. When you relaunch a website, change platform, restructure categories or rename pages, redirects are what stop old links, bookmarks and search results from leading to error pages. Done well, they help carry the value an old page has built up over to its replacement. Done badly or forgotten, they can lead to lost traffic and a frustrating experience.

This guide explains when redirects are needed, how to plan a redirect map, which type to use, how platforms such as Shopify and WordPress handle them, and what to check after launch.

When you need redirects

You need redirects whenever a page that people or search engines know about moves to a different address or is removed. Typical situations include:

  • A full website redesign with a new page structure.
  • Moving platform, for example from WooCommerce to Shopify or from Wix to WordPress.
  • Changing your domain name or moving from a subdomain to the main domain.
  • Renaming products, collections, categories or service pages.
  • Merging several thin pages into one stronger page.
  • Removing discontinued products or old blog posts.

Platform migrations deserve particular care because URL patterns usually change. Our guides to WooCommerce to Shopify migration and Wix to WordPress migration cover the wider process.

Types of redirect

Permanent redirects

A permanent redirect, known by its HTTP status code 301, or 308 in some setups, tells browsers and search engines the page has moved for good. Google treats a permanent redirect as a strong signal that the new address should replace the old one in search results. This is the type you want for almost every relaunch.

Temporary redirects

A temporary redirect, status 302 or 307, says the move is short term. It suits situations such as a page under maintenance or a seasonal campaign. Using temporary redirects for permanent moves can send mixed signals, so check what your platform or plugin uses by default.

Redirects to avoid

  • Redirect chains. Old page to newer page to newest page. Each hop slows things down and can dilute signals. Point old URLs straight to the final destination.
  • Redirect loops. Page A sends to page B, which sends back to A. Visitors see an error.
  • Mass redirects to the homepage. Sending every old URL to the homepage is confusing for visitors, and Google may treat irrelevant redirects like missing pages.
  • Client-side redirects. JavaScript or meta refresh redirects are less reliable than server-level ones. Use them only when nothing else is possible.

Building a redirect map

A redirect map is a simple spreadsheet listing each old URL and the new URL it should point to. It is the single most useful document in any relaunch.

Collect your old URLs

Gather addresses from several sources so nothing important is missed:

  • A crawl of the current site using a crawling tool.
  • Your XML sitemap.
  • Google Search Console, particularly the pages report and the performance report showing pages with clicks.
  • Google Analytics landing page reports.
  • Pages with links from other websites, found in Search Console's links report or a backlink tool.
  • Any URLs used in printed material, email campaigns or ads.

Match each URL to its closest equivalent

For each old address, pick the new page that best serves the same purpose. A product should go to the same product, a category to the matching category, a service page to the equivalent service page. Where no direct equivalent exists, choose the closest relevant page, such as a parent category.

Decide what to let go

Some pages genuinely have no replacement and little value, such as old test pages or very outdated content with no traffic or links. It can be reasonable to let these return a 404 or 410 status. A helpful 404 page then guides any stray visitors. See our 404 page design guide.

Keep URLs where you can

The best redirect is the one you do not need. If a new structure can keep important URLs unchanged, that is usually the safest option. Change addresses when there is a real reason, not just because a new site is being built.

How major platforms handle redirects

Shopify

Shopify includes URL redirects in the admin, with bulk import by CSV. Shopify uses fixed URL patterns for products, collections and pages, so moving from another platform almost always requires redirects. Shopify can also offer to create a redirect automatically when you change a product or page handle. Our Shopify SEO guide covers related settings.

WordPress and WooCommerce

WordPress can redirect automatically in some cases, but most sites use a redirect plugin or an SEO plugin with redirect features. Redirects can also be added at server level, which some hosts manage for you. Keep the number of plugins doing similar jobs low to avoid conflicts; our WordPress plugin audit guide can help.

Domain changes

When moving to a new domain, redirect each old URL to its matching page on the new domain, keep the old domain registered and redirecting for the long term, and use the change of address tool in Google Search Console where it applies.

Testing redirects before launch

Redirects should be tested on a staging site before going live wherever possible. Our guide to website staging and testing explains how to set one up.

  • Check a sample of old URLs from each section to confirm they land on the right page.
  • Use a crawler or redirect checker to spot chains and loops.
  • Confirm the status code is permanent, not temporary.
  • Check URLs with and without trailing slashes, uppercase letters and query strings if your old site used them.
  • Make sure internal links on the new site point directly to new URLs rather than relying on redirects.

What to check after launch

Launch day is the start of the redirect work, not the end.

  • Submit the new sitemap in Google Search Console and Bing Webmaster Tools.
  • Watch the pages report in Search Console for new not found errors and fix them with additional redirects where appropriate.
  • Monitor traffic and rankings for key pages. Some movement after a relaunch is normal while search engines process changes, but persistent drops on specific pages usually point to a redirect or content issue.
  • Re-crawl the old URL list to confirm every redirect still works.
  • Update links you control, such as social profiles, Google Business Profile, email signatures and directory listings.
  • Keep redirects in place. Removing them later can bring back broken links and lost signals.

Redirects for products and content you remove later

Redirects are not only a relaunch task. Online shops regularly retire products, and service businesses update or merge pages over time. Building a habit around these everyday changes keeps the site tidy.

  • Discontinued products. If a close replacement exists, redirect to it. If not, consider redirecting to the parent category, or keep the page live with a clear message and links to alternatives if it still attracts visitors.
  • Temporarily out of stock items. Keep the page live rather than redirecting, since it will return.
  • Merged articles. When combining several blog posts into one fuller guide, redirect each old post to the new one.
  • Renamed pages. Whenever a URL changes, add the redirect at the same time rather than leaving it for later.

Keep a running record of redirects added, with the date and the reason. It makes future relaunches far easier because you already know which old addresses matter.

Common redirect mistakes

  • Forgetting redirects entirely until traffic falls.
  • Only redirecting pages in the main navigation and ignoring blog posts, images or PDFs that earned links.
  • Pointing everything at the homepage.
  • Leaving the staging site open to search engines, creating duplicate content.
  • Changing several things at once, such as URLs, content and domain, without tracking which change caused what.

FAQs

Do redirects pass SEO value to the new page?

Google has said that permanent redirects pass signals to the new URL. Relevance still matters, so redirect to a genuinely equivalent page rather than an unrelated one.

How long should I keep redirects in place?

Ideally indefinitely. Old links on other websites and in bookmarks can keep sending visitors for a long time, and removing redirects brings back broken links.

Can I redirect all old pages to my homepage?

It is not recommended. Visitors expect to land on relevant content, and search engines may treat irrelevant homepage redirects much like missing pages.

What is the difference between a 404 and a 410?

A 404 means not found, while a 410 indicates the page has been deliberately removed. Both tell search engines the page is gone; use either for pages with no suitable replacement.

Do I need redirects if I only change the design, not the URLs?

If every URL stays exactly the same, you may not need new redirects. It is still worth crawling the old and new sites to confirm nothing has changed unexpectedly.
