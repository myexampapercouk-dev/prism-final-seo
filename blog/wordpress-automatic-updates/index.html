WordPress Automatic Updates: Core, Plugins and Themes Explained

How WordPress automatic updates work for core, plugins and themes, the trade-offs between safety and stability, and how to set a sensible update routine.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • WordPress can update core, plugins and themes automatically, and each can be controlled separately.
  • Automatic updates close security gaps quickly but can occasionally break a site without warning.
  • Backups, monitoring and a staging site make any update approach far safer.

Keeping WordPress up to date is one of the simplest ways to protect a site. Updates fix security issues, resolve bugs and keep everything compatible. The question most site owners face is not whether to update, but how: automatically in the background, or manually after checking each change.

WordPress has built-in automatic updates for core software, plugins and themes. This guide explains how they work, the trade-offs involved and how to choose a routine that suits your site.

What can WordPress update automatically?

There are three main parts of a WordPress site that receive updates:

  • WordPress core. The main software. Updates are split into minor releases, which are usually maintenance and security fixes, and major releases, which add features.
  • Plugins. Each plugin is updated by its own developer on its own schedule.
  • Themes. Your active theme and any installed themes also receive updates.

Translation files can update too, usually without anyone noticing.

By default, WordPress has long applied minor core updates automatically on most sites. Whether major core updates install automatically depends on your version and settings. Plugin and theme auto-updates are off by default but can be switched on for each one individually.

Where to find the settings

Core updates

Go to Dashboard, then Updates. Depending on your set-up, you may see an option to keep the site updated automatically with all new versions of WordPress, or only maintenance and security releases. Some hosts manage core updates for you and may change what you see here.

Plugin updates

On the Plugins screen, each plugin has an option to enable or disable auto-updates. You can also apply this to several plugins at once using bulk actions.

Theme updates

Under Appearance, then Themes, open the details for a theme to find its auto-update toggle.

Developers can also control updates in code through configuration settings and filters, which can override what appears in the dashboard. If the toggles are missing or greyed out, your host or developer has probably set a policy at that level.

The case for automatic updates

The main benefit is speed. When a security fix is released, sites that update automatically get it without waiting for someone to log in. For sites that are rarely checked, this can make a real difference.

Automatic updates also remove the build-up of pending updates. A site left for months can accumulate many outdated components, and updating them all at once is riskier than updating gradually.

Our guide to WordPress security explains why outdated software is a concern.

The case for manual updates

The trade-off is control. Occasionally an update introduces a conflict with another plugin, your theme or custom code. With automatic updates, you may only find out when a customer reports a problem.

Sites with more at stake from downtime, such as online shops, booking systems and sites with custom functionality, often prefer to review updates first. Manual updates let you:

  • Read the changelog before updating
  • Test on a staging copy of the site
  • Choose a quiet time to update
  • Check key pages and forms immediately afterwards

The risk is that manual updates get forgotten. A manual policy only works if someone is responsible for it and does it regularly.

A balanced approach

Many sites end up with a mix. One common pattern is:

  • Minor core updates automatic. These are generally small fixes.
  • Major core updates manual, applied after checking compatibility, ideally on staging first.
  • Simple, well-maintained plugins automatic, where a problem would be low impact.
  • Critical plugins manual, such as ecommerce, membership, forms and page builders, tested before going live.
  • Themes manual if they have been customised, or automatic if you use a child theme and the parent is stable.

There is no single right answer. The best approach depends on how complex your site is, how often someone checks it and how much disruption a fault would cause.

Safety nets that matter more than the setting

Whichever approach you choose, a few safeguards make updates far less stressful.

Backups

Take regular automated backups of both files and database, stored away from the server. Before manual updates, take a fresh backup. Check occasionally that backups can actually be restored.

Staging site

A staging site is a private copy of your live site where you can test updates. Many hosts offer one-click staging. Our guide to WordPress hosting covers what to look for.

Uptime and error monitoring

Monitoring tells you quickly if the site goes down. WordPress also emails the site administrator when automatic updates run, and may send a notice if a plugin update fails. Make sure the admin email address is one someone actually reads.

Recovery mode

If a plugin or theme causes a fatal error, WordPress can send a recovery mode link to the admin email. This lets you log in and deactivate the problem plugin even when the site is showing an error.

Site Health

The Site Health screen flags outdated software and other issues. Our guide to the WordPress Site Health screen explains how to read it.

Reducing what needs updating

Every plugin and theme is something else to keep updated. Removing what you do not need reduces both risk and maintenance work. Delete inactive plugins and unused themes rather than leaving them deactivated, keeping one default theme as a fallback if you wish. Replace abandoned plugins that no longer receive updates.

Our WordPress plugin audit guide walks through how to review what you have installed.

Premium plugins and themes

Plugins and themes bought from outside the official WordPress directory often need an active licence key to receive updates. If a licence lapses, updates may stop arriving without obvious warning. Keep a record of licences and renewal dates, and check that premium components are updating like everything else.

Custom code and updates

Sites with custom functionality need extra care. Code added directly to a parent theme is lost when that theme updates, which is one reason developers use child themes or small custom plugins instead. Our guide to WordPress child themes explains the approach.

Custom plugins written for your site do not receive updates from the WordPress directory. They need maintaining by whoever built them, especially when major WordPress or PHP versions change. If nobody is responsible for that code, it can become the weak point in an otherwise up-to-date site.

PHP and server software

WordPress runs on PHP and a database server, and these need updating too. They are usually managed by your host rather than from the WordPress dashboard. Older PHP versions eventually stop receiving security fixes, and newer plugins may require a more recent version. The Site Health screen shows which PHP version your site is running.

Changing PHP version can affect older plugins and themes, so test on staging first if you can. Many hosts let you switch PHP version from their control panel and switch back if something goes wrong.

Who is responsible?

Updates often slip because nobody is clearly responsible. If you work with a developer or agency, agree in writing who handles updates, how often, what testing happens and how problems are reported. If you manage the site yourself, put a recurring reminder in your calendar and keep a simple log of what was updated and when. A log makes it much easier to trace a problem back to the update that caused it.

After an update: what to check

A quick post-update check catches most problems early:

  • Load the homepage and a few key pages
  • Submit a contact form and confirm the message arrives
  • For shops, add a product to the basket and step through checkout
  • Log in to the admin and check the editor loads
  • Look at the site on a phone

With automatic updates, schedule this check regularly, for example after the update notification emails arrive.

FAQs

Are WordPress automatic updates safe?

They are generally reliable, and minor core updates are designed to be low risk. Any update can occasionally cause a conflict, so backups and monitoring are important.

Should I turn on auto-updates for all plugins?

Not necessarily. Many sites enable them for simple plugins and update critical ones, such as ecommerce or forms, manually after testing.

Why can I not see the auto-update option?

Your host or developer may control updates at the server or configuration level, which can hide or override the dashboard settings.

What happens if an automatic update breaks my site?

WordPress may send a recovery mode email to the admin address so you can deactivate the problem. You can also restore from a backup.

Do I still need to check my site if updates are automatic?

Yes. Automatic updates save time, but a regular check of key pages and forms makes sure nothing has quietly stopped working.
