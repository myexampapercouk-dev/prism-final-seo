Robots.txt Guide: How to Check, Edit and Test the File Safely

A robots.txt file tells search engine crawlers which parts of your site to skip. Learn how to check yours, edit it safely and avoid blocking pages by mistake.

By the Prism Works Studio team · 8 November 2026 · 9 min read

Key takeaways

  • Robots.txt is a short public text file that asks crawlers not to visit certain paths; it does not hide pages from Google search results on its own.
  • The most common small business problem is a leftover rule from a staging site that blocks the whole website, so check the file after every launch or migration.
  • Edit robots.txt through your platform's own settings where possible, keep rules few and simple, and test changes in Google Search Console before relying on them.

A robots.txt file is a small public text file at the root of your website that tells search engine crawlers which parts of the site they should not visit. For most UK small business websites it should be short, allow almost everything, and point to your XML sitemap, and the main job is making sure it is not accidentally blocking pages you want found.

It is one of those files that nobody looks at until something goes wrong. A website relaunches, traffic drops, and the cause turns out to be a single line left over from the development stage. This guide explains what the file does and does not do, how to find and read yours, how to edit it on common platforms, and how to test a change before it costs you visibility.

What robots.txt actually does

When a well-behaved crawler such as Googlebot or Bingbot arrives at your domain, one of the first things it requests is yourdomain.co.uk/robots.txt. The file contains groups of rules. Each group names a user agent (the crawler the rules apply to) and then lists paths that crawler is asked to stay out of with Disallow, or explicitly allowed with Allow. A Sitemap line can tell crawlers where your sitemap lives.

Three points are worth understanding before you change anything:

  • It controls crawling, not indexing. Blocking a page in robots.txt stops compliant crawlers reading it, but the address can still appear in search results if other pages link to it. To keep a page out of results, the usual method is a noindex instruction on the page itself, and the page must stay crawlable so the instruction can be seen.
  • It is a request, not security. Reputable search engines follow it. Scrapers and bad actors can ignore it. Anything private belongs behind a login, not in a Disallow line.
  • It is public. Anyone can read your robots.txt, so listing a sensitive folder there can draw attention to it.

Robots.txt sits alongside your sitemap as part of the basic technical setup. If you have not yet created or submitted a sitemap, our XML sitemap guide covers that side of things.

How to find and read your robots.txt file

Type your domain into a browser followed by /robots.txt. If a plain text page appears, that is your file. If you get a 404 error, you have no file, which simply means crawlers assume they may visit everything. That is not a disaster for a small site, but having a simple file with a sitemap reference is tidier.

Here is how to read the most common lines:

LineWhat it meansTypical use
User-agent: *The rules below apply to all crawlersThe default group on most sites
User-agent: GooglebotThe rules below apply only to Google's main crawlerRarely needed for small businesses
Disallow: /basket/Do not crawl anything starting with /basket/Baskets, checkouts, account areas
Disallow: /Do not crawl anything on the siteStaging sites only, never a live site
Disallow: (blank)Nothing is blockedA permissive default
Allow: /wp-admin/admin-ajax.phpAn exception inside a blocked folderCommon on WordPress
Sitemap: full URLWhere your XML sitemap livesRecommended on every site

Paths are case sensitive and match from the start of the address, so Disallow: /shop blocks /shop, /shop/ and /shopping-guide alike. That last point catches people out, and it is why a trailing slash matters.

What a sensible small business robots.txt looks like

For a brochure website with a contact form and a blog, a good file is often just a user-agent line for all crawlers, an empty or minimal Disallow, and a Sitemap line. There is usually no reason to block service pages, blog posts, images, CSS or JavaScript. Google renders pages much like a browser does, so blocking your stylesheets or scripts can stop it seeing your layout properly.

For an online shop, it can make sense to ask crawlers to skip areas that create endless low-value URLs: the basket, checkout, customer account pages and internal search results. Filter and sort parameters on category pages can also generate thousands of near-identical addresses, although how you handle those depends on whether any filtered pages are worth ranking. It is worth deciding that before adding any rules.

What you should almost never do on a live site is block whole sections of real content, block the entire site, or use robots.txt to try to remove pages from Google. Each of those creates more problems than it solves.

How to edit robots.txt

How you edit the file depends on your platform. Always check the platform's current help pages first, because settings move and names change.

WordPress: WordPress generates a virtual robots.txt by default. Many SEO plugins add an editor for it in their settings, which is the simplest route. You can also upload a physical robots.txt file to the root folder via your host's file manager or SFTP, which overrides the virtual one. Separately, check the reading settings: there is an option that discourages search engines from indexing the site, and it is often switched on during a build and forgotten. Our guide to WordPress reading and discussion settings explains where it lives.

Shopify: Shopify provides a default robots.txt that already blocks checkout, cart and similar areas, and for most stores it is fine as it is. Shopify allows edits through a theme template, but changes there are easy to get wrong and apply to the whole store, so treat it as a developer task. Our Shopify SEO guide covers the platform's wider quirks.

Wix, Squarespace and other builders: Hosted website builders usually manage the file for you and may offer limited editing in their SEO settings. Look for a robots.txt or SEO tools section in the dashboard, and read the builder's documentation before making changes.

Custom or static sites: On a custom build, robots.txt is a plain text file in the site's root folder. Edit it in a text editor, save it as plain text, and upload it in the same place. Keep a copy of the previous version so you can roll back.

Testing changes before and after you publish

A mistake in robots.txt can quietly remove large parts of a site from search over a few weeks, so test every change.

  1. Write down why you are changing it. If you cannot name the specific URLs you want crawlers to skip and why, leave the file alone.
  2. Check the paths against real URLs. List a handful of important pages, such as your homepage, top service pages and best-selling products, and confirm none of them start with a path you are about to disallow.
  3. Use Google Search Console. Search Console has a robots.txt report showing the version Google last fetched and any problems it found, and the URL Inspection tool tells you whether a given page is blocked. Our Google Search Console setup guide walks through getting access.
  4. Recheck after publishing. Load the live file in a browser to confirm the change is there, then keep an eye on the page indexing report over the following weeks.

Common robots.txt mistakes we see

Most robots.txt problems on small business sites fall into a few patterns:

  • The staging block goes live. A development site is correctly set to block everything, then the whole thing is copied to the live domain, rules and all. Our guide to website staging and testing explains how to keep the two apart.
  • Blocking a page you want removed from Google. If a page is blocked, Google cannot see a noindex tag on it, so it may stay listed with no description. Use noindex, and only block afterwards if there is a good reason.
  • Blocking CSS, JavaScript or image folders. This was common advice years ago and can now stop search engines rendering pages properly.
  • Typos and missing slashes. A single character can widen or narrow a rule. Disallow: /blog and Disallow: /blog/ do not behave the same way.
  • Several conflicting groups. Separate groups for different crawlers can override each other in ways that surprise people. Keep one simple group unless you have a specific need.
  • Forgetting after a migration. When URLs change during a relaunch, old Disallow lines may now point at nothing, or at new content. Our SEO migration checklist includes robots.txt in its pre-launch checks.

Robots.txt and AI crawlers

Many AI companies now run their own crawlers, and some publish user-agent names that site owners can address in robots.txt. Some businesses choose to block certain AI crawlers, while others want their content available so it can be cited in AI answers. There is no single right answer, and the list of crawler names changes over time, so check each company's own documentation for current names and what each crawler is used for. Be aware that blocking a crawler used for an AI search product may reduce your chances of appearing in it. Our guide to AI Overviews and SEO covers how visibility in AI-driven results works more broadly.

When to get help

If your site is a small brochure site with a default file and a sitemap line, you rarely need to touch robots.txt. It is worth a professional look if traffic has dropped after a relaunch, Search Console is reporting pages blocked by robots.txt that should be indexed, your shop generates large numbers of filter URLs, or you are planning a migration. FAQs

Do I need a robots.txt file for my small business website?

It is not strictly required. Without one, crawlers assume they may visit everything. A short file that allows crawling and points to your XML sitemap is still good practice, and many platforms create one automatically.

How to edit robots.txt on my website?

Use your platform's built-in option where there is one, such as an SEO plugin on WordPress or the theme template on Shopify. On a custom site, edit the plain text file in the root folder. Check the platform's current help pages first and test the result in Google Search Console.

Will blocking a page in robots.txt remove it from Google?

Not reliably. Robots.txt stops crawling, but a blocked URL can still appear in results if it is linked from elsewhere. To remove a page, use a noindex instruction on a page that remains crawlable, or remove the page and return an appropriate status code.

Should I block my basket and checkout pages?

On an online shop it is common to ask crawlers to skip basket, checkout and account pages because they have no search value. Many ecommerce platforms already do this by default, so check what your existing file contains before adding rules.

How quickly does Google notice a robots.txt change?

Google generally caches robots.txt for a period and refetches it regularly, so changes are usually picked up within a day or so, but the effect on indexing can take longer. Search Console's robots.txt report shows which version Google last fetched.

Can robots.txt stop AI tools using my content?

It can ask specific AI crawlers that respect robots.txt not to visit your site, if you name their user agents. It cannot stop crawlers that ignore the file, and blocking some crawlers may reduce visibility in AI search products, so weigh the trade-off first.
