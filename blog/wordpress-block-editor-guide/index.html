The WordPress Block Editor: A Practical Guide for Site Owners

How the WordPress block editor works, how to use blocks, patterns and reusable content, and how to keep pages consistent, accessible and easy to update.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • The block editor builds every page from individual blocks, such as paragraphs, images, buttons and columns.
  • Patterns and synced patterns help editors build consistent layouts without starting from scratch each time.
  • A well-configured editor, with sensible styles and limited options, keeps a site consistent as more people edit it.

If you have logged in to a WordPress website in recent years, you have almost certainly used the block editor, sometimes still called Gutenberg after the project that created it. It replaced the older classic editor, which worked much like a simple word processor, with a system where every piece of content is a separate block.

For some site owners the block editor feels natural straight away. Others find it confusing, especially if they learned WordPress before it arrived. This guide explains how the block editor works, the features that make day-to-day editing easier and how to set it up so your site stays consistent as it grows.

What is the block editor?

The block editor is the default way of creating and editing posts and pages in WordPress. Instead of one large text box, content is made up of blocks stacked on top of each other. A paragraph is a block. So is a heading, an image, a list, a button, a quote, a video or a set of columns.

Each block has its own settings. Select a block and a toolbar appears above it, with a settings panel on the right-hand side of the screen for options such as colour, spacing and alignment. Blocks can be moved up and down, duplicated, grouped together or removed.

The basics of working with blocks

Adding blocks

There are several ways to add a block. You can click the plus icon, which opens the block inserter, or simply start typing on a new line. Typing a forward slash followed by a block name, such as /image or /heading, is a quick shortcut that many regular editors come to rely on.

Moving and arranging

Blocks can be dragged, or moved with the up and down arrows in the toolbar. The List View, opened from the top toolbar, shows every block on the page in an outline, which is very useful on longer pages where blocks are nested inside groups and columns.

Layout blocks

Some blocks exist to hold other blocks. The Group, Row, Stack and Columns blocks let you arrange content side by side or wrap sections in a background colour. Understanding these container blocks is the key to building more structured layouts.

Undo and revisions

The editor has undo and redo buttons for recent changes, and WordPress keeps revisions of saved content, so you can usually restore an earlier version of a page if something goes wrong.

Patterns: ready-made layouts

Patterns are pre-designed groups of blocks that you can insert in one go: a hero section, a set of feature boxes, a call to action, a pricing table or a team grid. Themes often include their own patterns, and WordPress offers a shared pattern directory.

Patterns are one of the most useful features for business sites. Rather than rebuilding a section by hand each time, editors insert the pattern and change the text and images. That saves time and keeps sections looking consistent across the site.

Synced and unsynced patterns

Patterns can be synced or unsynced. An unsynced pattern is a starting point: once inserted, it becomes ordinary blocks you can edit freely. A synced pattern, previously known as a reusable block, stays linked everywhere it is used. Change it once and every instance updates.

Synced patterns are ideal for content that should be identical everywhere, such as a standard call to action, an opening hours box or a legal notice. Just remember that editing one instance changes them all, which can surprise editors who expected to change only one page.

Block themes and the Site Editor

Newer WordPress themes, known as block themes, extend the block approach beyond the page content. Using the Site Editor, you can edit headers, footers and page templates with blocks too, and set global styles for fonts, colours and spacing across the whole site.

Classic themes still work with the block editor for post and page content, but their headers, footers and templates are usually controlled through the Customizer or theme code instead. Knowing which kind of theme your site uses tells you where to go to change different parts of the site.

Block editor or page builder?

Before the block editor matured, many sites relied on page builder plugins to create flexible layouts. Page builders remain popular and can offer more design controls out of the box. The block editor has the advantage of being part of WordPress itself, which can mean less reliance on a third-party plugin and, depending on the build, lighter pages.

There is no single right answer. Our guide to WordPress page builders compares the options in more depth. What matters most is choosing one approach and using it consistently, rather than mixing several editors on the same site.

Keeping your site consistent

The flexibility of the block editor is also a risk. With every editor able to pick any colour, font size and spacing, a site can drift away from its brand over time. A few measures help:

  • Set global styles. Define your brand colours and typography centrally so editors pick from a limited palette rather than any colour.
  • Provide patterns for common sections. If editors have a ready-made, on-brand layout, they are less likely to improvise.
  • Limit available blocks where sensible. Developers can restrict which blocks appear for certain post types or users, hiding options that are not needed.
  • Lock key sections. Blocks and patterns can be locked so they cannot be moved or removed, protecting important parts of a template.
  • Write short editing guidelines. A simple document explaining which patterns to use and how to format headings goes a long way.

Accessibility and good structure

The block editor makes it easier to create well-structured content, but editors still need to use it correctly. Good habits include:

  • using heading blocks in a logical order, rather than making text bold and large to look like a heading,
  • adding meaningful alternative text to images in the image block settings,
  • writing descriptive link text instead of "click here",
  • using list blocks for lists, and
  • checking colour combinations for sufficient contrast.

These habits help visitors using screen readers and other assistive technology, and they also make your content clearer for search engines. Our guide to website accessibility covers the wider picture.

Performance considerations

Pages built with core blocks tend to be relatively light, but additional block libraries can add scripts and styles to every page. If you install a plugin for extra blocks, check whether you really need it and whether it loads assets only where those blocks are used. Large images dropped straight into image blocks are another common cause of slow pages; see our image optimisation guide for practical tips.

Extending the block editor

When core blocks do not cover what you need, there are options:

  • Block plugins add collections of extra blocks such as tabs, accordions or sliders.
  • Custom blocks can be built by a developer for specific needs, such as a product feature table that matches your design exactly.
  • Block variations and styles let developers offer pre-set versions of existing blocks, such as an outlined button style.

Custom blocks are often the cleanest way to give editors precisely the components they need, with fewer settings to get wrong.

Can I still use the classic editor?

The Classic Editor plugin restores the older editing screen. It can help during a transition, but the wider WordPress ecosystem, including themes and plugins, is increasingly built around blocks. For long-term maintainability, learning the block editor is usually the better investment. There is also a Classic block inside the block editor that holds older content until you convert it.

Common mistakes to avoid

  • Editing a synced pattern without realising it changes every page that uses it.
  • Choosing custom colours and sizes block by block instead of using global styles.
  • Installing several block libraries that overlap and slow the site.
  • Mixing a page builder and the block editor on the same pages.
  • Skipping heading levels or using headings purely for visual size.
  • Uploading oversized images without optimising them first.

FAQs

Is Gutenberg the same as the block editor?

Yes, in everyday use. Gutenberg was the name of the project that developed the block editor, and people still use the two names interchangeably.

Will switching to the block editor break my existing pages?

Existing content is usually kept inside a Classic block and continues to display. You can convert it to blocks when you are ready, checking the result as you go.

What is the difference between a pattern and a synced pattern?

An unsynced pattern is a starting layout you edit freely after inserting. A synced pattern stays linked, so editing it updates every place it appears.

Do I need a block theme to use the block editor?

No. Classic themes support the block editor for post and page content. Block themes additionally let you edit headers, footers and templates with blocks.

Can I restrict what editors can change?

Yes. Developers can limit available blocks, lock blocks and patterns, and set global styles so editors work within a defined design.
