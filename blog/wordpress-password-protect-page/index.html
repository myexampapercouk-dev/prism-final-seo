How to Password Protect a Page in WordPress (and When Not To)

How to password protect a page in WordPress using built-in visibility settings, what it does and does not protect, and better options for member areas.

By the Prism Works Studio team · 8 November 2026 · 7 min read

Key takeaways

  • WordPress can password protect any page or post from the Visibility setting in the editor, with no plugin needed.
  • Built-in protection hides the page content but not uploaded files, so never rely on it for genuinely sensitive documents.
  • For client portals, member areas or anything with personal data, use proper user accounts and roles instead of one shared password.

To password protect a page in WordPress, open the page in the editor, find the Visibility setting in the sidebar, choose Password protected, enter a password and update the page. Visitors will then see a password box instead of the content until they enter the correct password.

This guide is for UK small business owners who want to share a page with a limited audience, such as a price list for trade customers, a draft for a supplier or a gallery for one client. It covers the built-in method, what it actually protects, and when you need something more robust.

When a password protected page makes sense

A single shared password suits light-touch privacy, where the content would cause no real harm if someone outside the group saw it. Typical examples include:

  • A trade price list or wholesale catalogue for approved stockists.
  • A preview of a new page or campaign for colleagues or suppliers.
  • An event information page for ticket holders.
  • A simple gallery of finished work for one customer to review.
  • Internal guidance for staff that is not confidential.

It is not suitable for anything containing personal data, contracts, financial information or confidential business documents. Shared passwords get forwarded, and you cannot see who used them.

How to password protect a page in WordPress

The steps below use the block editor, which most current WordPress sites use. Our WordPress block editor guide explains the layout if it is unfamiliar.

  1. Open the page or post you want to protect from Pages or Posts in the dashboard.
  2. Open the settings sidebar if it is hidden, using the settings icon at the top right of the editor.
  3. Find the Visibility (or Status) option in the page summary panel. It normally shows Public.
  4. Choose Password protected and type a password into the box that appears.
  5. Save or update the page. The change takes effect immediately.
  6. Test it in a private browser window. While you are logged in, WordPress may show you the content directly, so check as a logged-out visitor.

If you use the classic editor, the same option sits in the Publish box next to Visibility. Some page builders show their own screens, but the underlying WordPress setting is the same and is usually reached from the standard editor or the page list's Quick Edit option.

The three visibility options compared

OptionWho can see itGood for
PublicEveryoneNormal pages and posts
Password protectedAnyone with the passwordLight-touch sharing with a small group
PrivateLogged-in users with suitable permissions, such as editors and administratorsInternal notes or pages not ready to share

Private pages need a WordPress login, so they are more controlled, but by default only users who can edit content see them. That makes them useful for internal content and less useful for customers. Our guide to WordPress user roles explains who can see what.

What built-in protection does not cover

This is the part most people miss. WordPress password protection hides the content of the page, but it has limits.

  • Uploaded files are not protected. Images, PDFs and other files in the media library have their own direct web addresses. If someone has that address, they can open the file without the password. Search engines can sometimes find these files too.
  • The page title is still visible. WordPress shows the title with "Protected" in front of it, and the page may appear in menus, archives or sitemaps unless you remove it.
  • One password for everyone. You cannot tell who viewed the page, and changing the password locks out everyone at once.
  • The password is remembered. WordPress stores a cookie so returning visitors do not need to type it again. That is convenient, but it also means anyone using the same device can see the page.
  • Caching can interfere. Some caching setups need configuring so protected pages are not served from cache. Test after enabling it.

Tidying up around a protected page

  • Keep it out of menus unless the audience needs a link. Our WordPress menus guide shows how to remove items.
  • Exclude it from your sitemap and search results. Most SEO plugins let you set a page to noindex and leave it out of the sitemap. Our XML sitemap guide explains what should be listed.
  • Use a clear, friendly message. The default text above the password box is plain. Some themes and plugins let you change it to explain who the page is for and how to get the password.
  • Choose a decent password and share it through a different channel from the link, for example the link by email and the password by phone.
  • Review it regularly. Protected pages are easy to forget. Change the password periodically and remove pages that are no longer needed. Our guide to WordPress trash and restoring content covers removing pages safely.

Common problems and how to fix them

Password protection is simple, but a few issues come up often enough to be worth knowing about before you send the link out.

  • The password box appears but the correct password does not work. Check for a stray space at the start or end, and remember passwords are case sensitive. If it still fails, a caching or security plugin may be interfering, so clear the cache and test again.
  • Visitors keep being asked for the password. The cookie that remembers the password may be blocked by the visitor's browser settings or cleared on exit. There is little you can change here, so tell people they may need to enter it again.
  • Some content still shows. Page builders sometimes place sections outside the main content area, such as headers, footers or sidebars set per page. Those can remain visible, so check the page logged out and move anything sensitive into the main content.
  • An excerpt shows on the blog page. For protected posts, check your archive and blog listing pages to make sure no summary or featured image gives away more than you intended.
  • You want to remove the protection. Open the page, set Visibility back to Public and update. The old password stops working straight away, so let your audience know.

Protecting a whole site temporarily

Sometimes the aim is to hide the entire site, for example while a new website is being built or tested. Password protecting each page is the wrong tool for that. Options include a coming soon or maintenance mode page, server-level password protection set up through your hosting panel, or a separate staging site that search engines are blocked from. Our guide to website staging and testing covers the last option.

When you need proper member access

If you find yourself creating several protected pages, sharing passwords with dozens of people or worrying about who has access, you probably need individual accounts. That might mean:

  • A client or trade portal where each customer logs in with their own details.
  • A membership or course area that controls access by plan or purchase.
  • Protected file downloads that check the user is logged in before serving the file.
  • Wholesale pricing in a shop, where approved trade accounts see different prices.

Each of these handles personal data, so think about your privacy notice, retention and security. Check current ICO guidance, and keep login pages protected with strong passwords and two-factor authentication where available. Our WordPress security guide covers the basics.

FAQs

How do I password protect a page in WordPress?

Open the page in the editor, find Visibility in the settings sidebar, choose Password protected, enter a password and update. Test it in a private browser window, because logged-in users may see the content without a prompt.

Do I need a plugin to password protect WordPress pages?

No. WordPress includes password protection for individual pages and posts. Plugins are only needed for extra features, such as protecting a whole site, using individual logins or protecting uploaded files.

Are files on a password protected page also protected?

No. Images and documents in the media library keep their own direct addresses, which can be opened without the password. Use a member or download protection solution for files that genuinely need to stay private.

What is the difference between private and password protected?

A private page is only visible to logged-in users with suitable permissions, such as editors and administrators. A password protected page can be seen by anyone who has the password, with no login needed.

Can I password protect my whole WordPress site?

Not neatly with page-level settings. Use a coming soon or maintenance mode plugin, server-level password protection from your host, or a staging site while the site is being built or rebuilt.

Will a password protected page appear in Google?

The content is hidden, but the page address and title can still be found. Set the page to noindex in your SEO plugin, leave it out of your sitemap and remove it from public menus.
