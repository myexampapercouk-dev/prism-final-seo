WordPress Font Loading: How to Use Web Fonts Without Slowing Your Site

How web fonts load on a WordPress site, how to host fonts locally, limit weights and avoid layout shift, plus privacy points UK site owners should consider.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Every font family, weight and style is a separate file the browser must download, so fewer is usually better.
  • Hosting fonts on your own site and using the site editor's font tools gives you more control over speed and privacy.
  • Sensible fallback fonts and font display settings stop text from vanishing or jumping while fonts load.

Fonts shape how a website feels. The right typeface can make a small business look established, friendly or premium. But web fonts are files the browser has to fetch before it can draw text in them, and on a WordPress site they can quietly pile up: one font chosen in the theme, another added by a page builder, a third pulled in by a form tool. The result can be slower pages, text that flickers or jumps as it loads, and requests sent to outside servers you never meant to use.

This guide explains how font loading works on WordPress, how to see what your site is actually loading, and practical steps to keep typography looking good without dragging performance down. It is written for UK small business owners and the people who look after their sites.

How web fonts load

When a browser opens a page, it reads the HTML and the stylesheets. When a stylesheet says a heading should use a particular font, the browser checks whether that font is available. If it is a web font, the browser requests the font file from wherever it is hosted. Until that file arrives, the browser either shows nothing in that spot, shows a fallback font, or waits briefly then shows a fallback.

Each combination of family, weight and style is usually its own file. Regular, bold, italic and bold italic of one family can mean four downloads. Add a second family for headings with two weights and you have six. Every extra file adds work for the browser, particularly on mobile connections.

Where fonts come from on a WordPress site

Fonts can enter a WordPress site from several places:

  • The theme, which may bundle its own fonts or load them from an external font service.
  • The site editor, in block themes, where you can install and choose fonts under Styles and Typography.
  • Page builders, which often have their own font settings and may load fonts separately from the theme.
  • Plugins, such as sliders, forms or icon tools, which can load their own fonts or icon fonts.
  • Custom code added by a developer in a child theme or settings box.

Because these sources work independently, it is easy to end up loading the same family twice or loading fonts that no longer appear anywhere on the page.

Find out what your site is loading

Before changing anything, check what is happening now. Open a page in a desktop browser, open the developer tools, go to the network panel, filter by font and reload. You will see each font file, its size and where it came from.

Look for:

  • Fonts loaded from external domains rather than your own.
  • More weights than your design actually uses.
  • Two copies of the same family from different sources.
  • Icon fonts loaded for a handful of small icons.

Repeat this on a few page types, such as the homepage, a blog post and a contact page, as different templates and plugins may load different fonts.

Limit families and weights

The simplest improvement is often using fewer fonts. Many well-designed sites use one family for everything, or one for headings and one for body text. Within each family, choose only the weights you need. A typical pairing might be regular and bold for body text, plus one weight for headings.

Some font families are available as variable fonts, where a single file contains a range of weights. These can reduce the number of files, though a single variable file may be larger than one static weight. Whether it helps depends on how many weights you use.

Our article on website colour and typography covers choosing fonts from a design perspective.

Host fonts on your own site

Loading fonts from an external service means the visitor's browser connects to another server, which adds a connection step. It also means visitor information, such as their IP address, is sent to that third party.

In the UK, data protection law covers personal data such as IP addresses, and there has been legal debate in Europe about loading fonts from external services without a clear basis. How this applies to your site depends on your circumstances, so take advice if you are unsure. Hosting fonts locally sidesteps the question for fonts and keeps loading under your control.

Using the site editor

Recent versions of WordPress include a font library in the site editor for block themes. You can upload font files or install fonts, and WordPress stores them on your own site. Check the licence of any font before uploading it; many fonts allow web use, but terms vary.

Classic themes and page builders

For classic themes, a developer can add font files to a child theme and declare them in its stylesheet. Many page builders also have a setting to load fonts locally rather than from an external service. Our guide to WordPress child themes explains why custom changes belong in a child theme.

Control how text behaves while fonts load

The font display setting tells the browser what to do while a web font is downloading. The swap value shows text in a fallback font immediately and switches when the web font arrives. This avoids invisible text, which is important for readability, but can cause a visible change as fonts swap.

Many themes and the site editor set this for you. If you are working with custom font declarations, ask your developer which setting is used.

Choose a sensible fallback

The fallback font is what visitors see before the web font loads, or if it fails. Picking a system font with similar width and height to your web font reduces the jump when the swap happens. Large differences can push content around, which is irritating for readers and counts towards layout shift measurements.

Preloading key fonts

Preloading tells the browser to start downloading a file early, before it discovers the font in the stylesheet. For the one or two fonts used above the fold, typically the main body and heading fonts, preloading can help text appear in the right font sooner.

Preload sparingly. Preloading many files competes with other important resources such as the main image and stylesheets. If you preload a font the page does not use, the browser downloads it for nothing.

Subsetting and file formats

Font files often include characters for many languages. If your site is in English, a subset containing only the characters you need can be much smaller. Some font services subset automatically; for self-hosted fonts, subsetting may need to be done before upload. Take care to include characters you do use, such as the pound sign, accented letters in names and typographic quotation marks.

Modern browsers support the WOFF2 format, which is compressed and generally the best choice for the web. Older formats are rarely needed now.

Icon fonts

Some themes and plugins load an entire icon font to display a few icons, such as social media symbols or arrows. These files can be surprisingly large. Inline SVG icons are usually lighter and more accessible. If your site loads an icon font for only a handful of icons, it may be worth asking a developer about replacing them.

Check the results

After making changes, clear any caching, reload the page with the network panel open and confirm the expected fonts load from the expected place. Test on a mobile phone too. Look for text that flickers, jumps or appears in the wrong font. Speed testing tools can help confirm that layout shift and loading times have not got worse. Our guide to website speed optimisation covers testing in more detail.

Make changes on a staging copy first if you can, especially on a busy site. Theme and plugin updates can occasionally reintroduce external fonts, so recheck after major updates.

FAQs

Do web fonts slow down a WordPress site?

They add files the browser must download, so they can. The effect depends on how many families and weights you use and how they are loaded. A small, well-chosen set has a modest impact.

Is it better to host fonts locally?

Often, yes. Local hosting avoids an extra connection to another server and keeps visitor data away from third parties. Check the font's licence allows self-hosting.

Why does my text change font after the page loads?

The browser is showing a fallback font while the web font downloads, then swapping. Choosing a closer fallback and preloading key fonts can reduce how noticeable this is.

Can I use any font I like on my website?

Only if the licence allows web use. Some fonts are free for web use, others need a paid licence, and desktop licences do not always cover websites.

How many fonts should a small business website use?

There is no rule, but one or two families with a few weights is enough for most designs and keeps loading light.

Will changing fonts affect my search rankings?

Fonts themselves are not a ranking factor, but page experience can play a part. Faster, more stable pages are better for visitors either way.
