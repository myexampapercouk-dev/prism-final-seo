WordPress Site Editor Styles: Managing Global Fonts and Colours

How global styles work in the WordPress Site Editor, including fonts, colour palettes, spacing and style variations, and how to keep a block theme on brand.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Global styles let you set fonts, colours and spacing once for the whole site in a block theme.
  • A small, deliberate palette and type scale keeps editors on brand and pages consistent.
  • Style changes made in the editor are stored in the database, so document and back them up.

If your WordPress site uses a block theme, much of its look is controlled from one place: the Styles panel in the Site Editor. From there you can set fonts, colours, spacing and the appearance of individual blocks for the whole site, without touching code. Used well, global styles keep every page consistent and on brand. Used carelessly, they can produce a site where every page looks slightly different and nobody is sure why.

This guide explains how global styles work, what you can control, and how to set them up so your team can edit content confidently without breaking the design.

What are global styles?

Global styles are site-wide design settings in block themes. Instead of styling each block on each page, you define defaults once: the body font, heading sizes, link colours, button styles, spacing and so on. Every block then inherits those defaults unless someone overrides them.

The settings come from three layers:

  • The theme. A block theme ships with a configuration file that defines available fonts, colours, sizes and default styles.
  • User customisations. Changes you make in the Styles panel are saved to the database and sit on top of the theme defaults.
  • Individual blocks. Editors can still change the style of a single block on a single page, which overrides both of the above.

Understanding these layers helps when something looks wrong. If a heading is the wrong colour, the cause could be in any of them.

Finding the Styles panel

In a block theme, go to Appearance, then Editor, then Styles. You will see a preview of the site alongside options for typography, colours, layout and blocks. Changes preview immediately and only go live when you save.

If you do not see the Site Editor, your site is probably using a classic theme. Classic themes handle design through the Customizer or theme options instead. Our WordPress block editor guide explains the difference between the editing experiences.

Typography

The typography section controls fonts and text sizes for the site and for specific elements such as headings, links, captions and buttons.

Choosing fonts

Recent WordPress versions include a font library where you can manage the fonts available to your site, including uploading font files you have the right to use. Keep the selection small. One font for headings and one for body text is usually plenty, and every extra font adds weight to your pages.

Check the licence for any font before uploading it. Some fonts are free for web use, others require a licence, and terms vary. If in doubt, ask whoever supplied your brand guidelines.

Setting a type scale

Block themes define a set of font sizes, often labelled small, medium, large and so on. Editors pick from these in the block toolbar. A clear, limited scale stops pages ending up with dozens of slightly different text sizes. Many block themes also support fluid typography, where text sizes adjust smoothly between small and large screens.

Headings and line height

Set heading styles at the element level so every H2 looks the same across the site. Check line height and letter spacing too. Generous line height on body text helps readability, especially on mobile.

Colours

The colour section has two parts: the palette and the element colours.

The palette

The palette is the set of colours editors can choose from when styling blocks. A theme provides a default palette, and you can add custom colours. For brand consistency, define your brand colours here with clear names such as Primary, Accent and Neutral, and consider disabling the option for editors to pick any custom colour if your theme allows.

Element colours

Element colours set the defaults for text, background, links, headings, buttons and captions. Set these deliberately so a new page looks right before anyone touches the colour controls.

Contrast

Every combination of text and background needs enough contrast to be readable. The editor may warn about low contrast in some places, but do not rely on it. Check key combinations, including link colours, button text and text on coloured backgrounds, with a contrast checker. Our guide to website accessibility covers why this matters.

Layout and spacing

The layout section controls content width, wide width and spacing between blocks. Content width is the default width of text, while wide width applies to blocks set to wide alignment.

Spacing presets work like font sizes: the theme defines a scale and editors pick from it. Consistent spacing is one of the quieter signals that a site has been designed carefully. Setting block gap and padding defaults globally means editors rarely need to adjust spacing by hand.

Styling individual block types

Under Blocks in the Styles panel you can set defaults for each block type. For example, you might give every Quote block a particular border and font style, or make every Button block use your brand colour with rounded corners.

This is more powerful than styling blocks one at a time on the page. When you change the default, every instance across the site updates. It also reduces the temptation for editors to restyle blocks individually.

Some blocks also support block style variations, which are alternative looks you can switch between, such as an outline button versus a filled one.

Style variations

Many block themes include style variations: complete alternative sets of fonts and colours that you can switch between in one click. They are a quick way to try a different look, but switching variation on a live site changes everything at once. Preview carefully and save only when you are sure.

Developers can also create custom style variations for a brand, for example a seasonal palette, so the change can be made and reversed cleanly.

Where changes are stored, and why it matters

Customisations made in the Styles panel are saved in the database, not in the theme files. This has a few consequences:

  • Theme updates do not overwrite them. Your customisations sit on top of the theme.
  • They do not travel with the theme files. If you move the theme to another site, your customisations stay behind unless you export them.
  • They can be reset. The Styles panel has an option to reset to theme defaults, which removes your changes.

Back up the database regularly and keep a note of key design decisions. For more permanent changes, a developer can move styles into a child theme so they live in version-controlled files. Our guide to WordPress child themes explains the approach.

The editor also keeps a revision history for global styles, so you can look back at earlier versions and restore one if a change goes wrong.

Keeping editors on brand

Global styles work best when combined with sensible limits on what editors can change. Options include:

  • Restricting the colour palette to brand colours only
  • Disabling custom font sizes so editors use the defined scale
  • Using patterns and synced patterns for common layouts
  • Locking parts of templates that should not change
  • Giving most users editor or author roles rather than administrator access

Our guides to WordPress synced patterns and WordPress user roles go into these options in more detail.

Common problems and fixes

A block ignores the global style

Someone has probably set a style on that block directly. Select the block and clear its custom colour or typography settings so it inherits the defaults again.

Fonts look different from the brand guidelines

Check that the correct font files and weights are installed. If a weight is missing, the browser may fake it, which often looks wrong.

Changes do not appear on the live site

Clear any caching on the site or server. Caching layers often hold onto old stylesheets.

The site looks different after a theme update

The theme may have changed its defaults. Your customisations should remain, but anything you had not customised will follow the new theme defaults.

FAQs

Do global styles work with classic themes?

No. The Styles panel is part of the Site Editor, which is available with block themes. Classic themes use the Customizer or their own settings instead.

Will updating my theme remove my style changes?

Changes made in the Styles panel are stored separately in the database, so a theme update should not remove them. Theme defaults you have not customised may change, so review the site after updates.

Can I upload my brand font?

Recent WordPress versions let you upload font files through the font library. Check that your font licence allows web use first.

How do I undo a style change?

Use the revision history in the Styles panel to restore an earlier version, or reset to theme defaults if you want to start again.

Should editors be able to pick any colour?

Usually not. Restricting choices to a brand palette keeps the site consistent and helps make sure colour combinations remain readable.
