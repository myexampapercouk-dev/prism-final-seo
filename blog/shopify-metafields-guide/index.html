Shopify Metafields: How to Add Custom Product Information Without Apps

A practical guide to Shopify metafields and metaobjects: what they are, how to plan them, show them in your theme and use them for filters and product details.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Metafields store extra structured information, such as materials or care instructions, that standard Shopify fields do not cover.
  • Plan definitions and value types before entering data, so information stays consistent and can power filters.
  • Online Store themes can display metafields through dynamic sources in the theme editor, often without custom code.

Shopify metafields are custom fields that let you store extra information about products, variants, collections, customers, orders and more. They fill the gaps left by Shopify's standard fields. If you need to show ingredients, dimensions, care instructions, a size guide or a downloadable spec sheet consistently across products, metafields are usually the right tool.

This guide explains how metafields and metaobjects work, how to plan them and how to display them in your theme. If you are customising your theme more broadly, our Shopify theme customisation guide is a good companion.

What metafields are

Every product in Shopify has standard fields: title, description, price, images, vendor, product type and tags. Many shops need more. Without metafields, that extra detail tends to end up crammed into the description, which makes it hard to format consistently, filter or reuse.

A metafield has:

  • A definition, which you create once under Settings, Custom data. It names the field and sets where it applies, such as products.
  • A type, such as single line text, rich text, number, true or false, date, file, URL, colour, or a reference to another resource.
  • Optional validation, such as a list of allowed values or a minimum and maximum.
  • Values, which you fill in on each product's edit page.

Shopify also offers standard definitions for some common fields, and category metafields linked to its product taxonomy. Check what already exists before creating your own.

Metaobjects: reusable content blocks

Metaobjects go a step further. They let you define a structured content type, with several fields, and create entries you can reuse. For example:

  • A material entry with a name, description and care image, referenced by many products.
  • A designer or maker profile shown on related products.
  • A size guide table reused across a whole category.
  • A store location with address and opening hours.

When you update a metaobject entry, every product that references it shows the change. That saves repetitive editing and keeps information consistent.

Planning before you build

Metafields work best when planned. Adding them ad hoc can lead to near-duplicate fields and inconsistent values.

  1. List the information shoppers need to choose and use your products. Customer questions and returns reasons are a useful source.
  2. Decide what is shared and what is unique. Shared information suits metaobjects; product-specific details suit plain metafields.
  3. Choose the right type. Use numbers for measurements so they can be compared, lists of allowed values for things like material, and rich text only where formatting is genuinely needed.
  4. Name fields clearly and add short descriptions in the definition so whoever edits products knows what to enter.
  5. Decide which fields should be filters on collection pages.

Writing this plan down also helps if you later brief a developer. Our guide on how to brief a Shopify developer covers what to include.

Adding values to products

Once a definition exists, its field appears near the bottom of each product's edit page. You can fill values in one product at a time, use the bulk editor for many products, or import them in a product CSV where supported. For larger catalogues, check the current Shopify documentation on importing metafield values, as options change over time.

Consistency matters more than volume. A filter that only works for half your products frustrates shoppers. If you add a new field, plan to fill it across the relevant range.

Showing metafields in your theme

With Online Store themes, many sections and blocks support dynamic sources. In the theme editor, you can connect a text, image or other setting to a metafield instead of typing a fixed value. The block then shows each product's own value.

Common uses include:

  • A "Materials" or "Care" collapsible tab on the product page.
  • A badge such as "Handmade in the UK" driven by a true or false field.
  • A downloadable instruction PDF linked from a file field.
  • A size guide pulled from a metaobject referenced by the product.

If your theme does not offer the block you need, a developer can add metafields to templates using Liquid. That is usually a small, contained change. Test it on a duplicate theme first.

Using metafields for filters and collections

Shopify's Search and Discovery app can use certain product and variant metafields as filters on collection and search pages. This is often cleaner than relying on tags, because values are controlled and spelled consistently.

Metafields can also be used as conditions in automated collections, depending on the field type. That lets you build a collection such as "Organic cotton" from a material field rather than remembering to tag each product. Our ecommerce site search guide covers related ideas.

Metafields and SEO

Metafields do not boost rankings on their own. What they do is help you present clear, consistent, useful product information, which supports both shoppers and search engines. Some themes and apps can also use metafield values in structured data, such as product materials. Keep descriptions written for people, and use metafields to organise the supporting detail. Our product descriptions guide explains how the two work together.

Metafields versus apps

Before Shopify expanded custom data, many stores used apps for tabs, size charts and badges. Some of those features can now be built with metafields and theme blocks, which may mean fewer scripts and fewer subscriptions. Apps still make sense for complex features. When reviewing your apps, check whether any of them only display information that a metafield and a theme block could now handle.

A sensible way to decide is to ask three questions. Does the feature only display stored information? Does it need logic, such as calculations or customer-specific content? Does it need regular updates from a third party? Display-only features are good candidates for metafields. Features with logic or external data are often better left to a well-supported app or custom development.

Worked examples

A homeware shop

A homeware shop might create number metafields for width, height and depth, a list field for material, and a rich text field for care instructions. The product page shows dimensions in a tidy table, a care tab pulls in the instructions, and collection pages let shoppers filter by material. Nothing needs to be typed into the description twice.

A skincare brand

A skincare brand might create an ingredient metaobject with a name and short explanation, then reference several ingredients from each product. A "Key ingredients" block lists them on the product page. If the explanation of an ingredient changes, it is updated once and every product reflects it. Any claims about ingredients still need to follow the relevant advertising rules, so check guidance from the ASA and take advice where unsure.

A clothing label

A clothing label might use a metaobject for size guides, one per garment type, and a product reference so each product points at the correct guide. A true or false field could control a "Made in the UK" badge, shown only where it is accurate.

Common mistakes to avoid

  • Creating several fields that mean the same thing, such as "Material" and "Fabric".
  • Using free text where a list of allowed values would keep data consistent.
  • Showing an empty block on products where the field has not been filled.
  • Deleting a definition that the theme still references.
  • Putting long marketing copy into metafields that should live in the main description.

Keeping custom data tidy

  • Review definitions occasionally and remove unused ones carefully, after checking nothing in the theme references them.
  • Avoid creating a new field when an existing one could be reused.
  • Restrict who can edit definitions, while letting product editors fill in values.
  • Note which theme sections rely on which fields, so future changes do not break the storefront.

FAQs

Do I need an app to use Shopify metafields?

No. You can create metafield definitions and metaobjects in Settings, Custom data, and show them through dynamic sources in compatible themes. Apps are only needed for specialised workflows.

What is the difference between a metafield and a metaobject?

A metafield adds one piece of information to a resource, such as a product. A metaobject is a reusable entry with several fields that many resources can reference.

Can customers filter by metafields?

Often, yes. Shopify's Search and Discovery app supports certain metafield types as filters. Check which types are supported in the current documentation.

Will metafields work with my theme?

Most current Online Store themes support dynamic sources for common blocks. Older or heavily customised themes may need some Liquid code to display metafields.

Should I use tags or metafields?

Tags are quick but free-form, so typos slip in. Metafields with defined types and allowed values are usually more reliable for filters and structured product details.
