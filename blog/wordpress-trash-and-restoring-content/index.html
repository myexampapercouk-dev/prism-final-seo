WordPress Trash: How to Restore Deleted Pages, Posts and Media

How the WordPress trash works, how to restore deleted pages, posts and comments, what happens to media, and habits that stop content disappearing for good.

By the Prism Works Studio team · 1 November 2026 · 7 min read

Key takeaways

  • Deleted posts and pages go to the trash first, where they can usually be restored with one click.
  • Items in the trash are removed permanently after a set period, so restore anything important promptly.
  • Regular backups and sensible user permissions are the real safety net for lost content.

Sooner or later, someone deletes something on a WordPress site that they did not mean to. It might be a page tidied away during a clean-up, a post removed by a new team member, or a batch of items deleted in bulk by mistake. The good news is that WordPress includes a trash feature designed exactly for this situation.

This guide explains how the WordPress trash works, how to restore different types of content, what happens to images and other media, and how to put habits in place so that a deletion never turns into a lasting problem.

How the WordPress trash works

When you delete a post or page in the WordPress dashboard, it is not removed straight away. Instead, it is moved to the trash. Think of it like the recycle bin on a computer. The content is hidden from your live site and from the main list of posts or pages, but it still exists in the database and can be brought back.

By default, WordPress automatically and permanently empties items from the trash after a set number of days. Site developers can change that period, or disable the trash entirely, through configuration settings. If your site behaves differently from what you expect, it is worth checking with whoever built or maintains it.

What goes to the trash

The trash applies to several types of content:

  • Posts, including blog articles and news items.
  • Pages, such as service pages, contact pages and landing pages.
  • Comments, which have their own trash separate from spam.
  • Custom content types added by your theme or site build, which usually follow the same pattern.

Media works differently, which we cover below. Categories, tags, menus and users are also handled differently, and deleting them is usually immediate rather than going to a trash.

How to restore a deleted post or page

Restoring content is straightforward:

  1. In the dashboard, go to Posts or Pages, depending on what was deleted.
  2. At the top of the list, look for the Trash link next to the counts for All, Published and Drafts. It only appears when there is something in the trash.
  3. Hover over the item you want back and click Restore.

In recent versions of WordPress, a restored item comes back as a draft rather than going straight back live. This gives you a chance to check it before republishing. Open the item, review the content, and publish it again when you are happy.

To restore several items at once, tick the boxes next to them in the trash view, choose Restore from the bulk actions menu and apply it.

Checking the restored content

Before you republish, run through a few checks:

  • Web address. Confirm the slug is the same as before, so existing links and search results still work. If WordPress has added a number to the end because a similar slug now exists, fix that first.
  • Parent page. For pages, check the parent setting is still correct so the page sits in the right place in your site structure.
  • Featured image and media. Make sure images still display, especially if anything was removed from the media library.
  • Menus. Deleting a page can remove it from navigation menus. You may need to add it back under Appearance or in the site editor.
  • Publish date. Check whether the original date has been kept, particularly for blog posts where the date is shown.

Restoring an earlier version instead

Sometimes the problem is not that a page was deleted, but that it was edited badly. In that case, the trash will not help. WordPress revisions let you compare and roll back to an earlier saved version of a post or page. Our guide to WordPress revisions and autosave explains how that works.

What happens to deleted media

Images, documents and other files in the media library behave differently. By default, deleting a media item removes it permanently, and WordPress will warn you before it does. There is no trash step unless the site has been configured to use one for media.

That makes media deletions riskier. If an image used across several pages is removed, every page that relied on it will show a broken image. Before deleting media, check where it is used. When tidying a media library, it is often safer to leave files in place unless you are certain they are no longer needed.

If media has been deleted permanently, the realistic route back is usually a backup, or re-uploading the original file if you still have it.

Restoring deleted comments

Comments have their own trash. Go to Comments in the dashboard, select the Trash view, and restore any comment that was removed by mistake. Spam is held separately, and comments marked as spam can be moved back if they were genuine.

Emptying the trash

You can empty the trash manually using the Empty Trash button, or delete individual items permanently. Once you do that, the content is gone from the dashboard and can only be recovered from a backup.

There are good reasons to empty the trash now and then, such as keeping the admin tidy. Just make sure the items are genuinely not needed, and that someone with the right knowledge has checked before you do.

When content cannot be restored from the trash

If something has been permanently deleted, or the trash was emptied automatically, the options are more limited:

  • Site backups. A recent backup is the most reliable way to recover lost content. Restoring a full backup can overwrite newer changes, so it is often better to extract the specific content you need, which may need a developer.
  • Hosting snapshots. Many hosts keep their own backups. Check your hosting control panel or contact their support.
  • Cached or archived copies. Sometimes text can be recovered from cached copies, emails or documents where it was drafted. This is a last resort, but better than starting again.

Preventing accidental deletions

The trash is a safety net, but a few habits reduce the need for it:

  • Use appropriate user roles. Not everyone needs permission to delete published pages. Giving people only the access they need reduces risk. Our guide to WordPress user roles explains the options.
  • Keep regular, tested backups. Make sure backups run automatically, are stored away from the site itself, and can actually be restored.
  • Agree a clean-up process. Before removing old content, list what will go, check for links and decide whether anything should redirect elsewhere.
  • Draft rather than delete. If you are unsure about a page, switching it to draft or private hides it without removing it.
  • Be careful with bulk actions. Double check your selection before applying a bulk delete.

Deleting pages on purpose

When you do remove a page deliberately, think about the visitors and search engines that might still be looking for it. If there is a closely related page, a redirect can send people there instead of a dead end. If the content is simply gone, a helpful 404 page keeps visitors on your site. Planning this before deletion avoids broken links and lost traffic.

Trash in the block editor

You can also move content to the trash from inside the editor itself. In the block editor, the option usually sits in the post or page settings panel. This is convenient but easy to click by mistake, particularly when several people edit the same site. If someone reports that a page has vanished, the trash is the first place to check.

Keeping a record of changes

On sites with several editors, it helps to know who deleted what and when. WordPress does not keep a detailed activity history by default, so many teams agree simple rules instead, such as noting major removals in a shared document or only allowing certain roles to delete published content. Whatever approach you choose, the aim is to make deletions deliberate and traceable rather than accidental and mysterious.

FAQs

How long do items stay in the WordPress trash?

WordPress removes trashed items automatically after a default period, which developers can change. If you need something back, restore it as soon as you notice it is missing.

Why did my restored page come back as a draft?

Recent versions of WordPress restore trashed content as a draft so you can review it before it goes live again. Check the content and publish it when ready.

Can I recover an image I deleted from the media library?

Media deletions are usually permanent by default. The main options are restoring from a backup or re-uploading the original file.

Does deleting a page affect my search rankings?

It can, if the page received visits from search or links from other sites. Restoring it quickly, or redirecting it to a relevant alternative, helps reduce the impact.

Who can delete content in WordPress?

It depends on user roles. Administrators and editors can usually delete most content, while authors and contributors have more limited permissions over their own work.
